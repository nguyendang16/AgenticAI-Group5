Framework 1: KG Quality

Based on Zaveri et al. Linked Data quality dimensions: completeness, consistency, provenance, conciseness, and availability.

What this checks

This evaluation asks whether the graph is usable as a reliable knowledge source. For this project, that means each review criterion should have a stable ID, name, group, description, evidence requirement, article/domain applicability, and source document provenance.

These checks matter more than link prediction for the current system because the review agent uses the KG as a retrieval and grounding layer. If provenance or required properties are missing, the generated review cannot explain where its criteria came from.

Framework 2: PyKEEN Link Prediction

Real PyKEEN TransE evaluation compared against a typed tail-popularity baseline. Higher MRR and Hits@K are better; lower MR is better.

What this checks

Link prediction tests whether a model can hide one part of a graph triple and predict it back. Example: given ReviewCriterion - REQUIRES_EVIDENCE - ?, the model ranks possible evidence nodes and gets a better score when the correct node is near the top.

PyKEEN trains an embedding model, here TransE, on training triples and evaluates it on held-out test triples. This is useful when a KG has enough repeated structure to learn missing links, but it is less informative for a small hand-curated graph with mostly unique criteria and evidence nodes.

How to Read the Metrics

Metric Meaning Direction
MRR Mean reciprocal rank. Rewards putting the correct answer near rank 1. Higher is better
MR Mean rank of the correct answer among candidates. Lower is better
Hits@1 Fraction of test triples where the correct answer is ranked first. Higher is better
Hits@3 Fraction where the correct answer appears in the top 3. Higher is better
Hits@10 Fraction where the correct answer appears in the top 10. Higher is better

What the Baseline Means

The typed tail-popularity baseline is a simple non-learning comparison method. It does not train embeddings. Instead, for each relation type, it ranks candidate tail nodes by how frequently they appeared with that relation in the training graph.

A baseline is important because it tells us whether the learned model is actually adding value. In this benchmark, the baseline outperforms TransE, which suggests that the current KG does not yet contain enough rich graph structure for embedding learning to beat a simple frequency-based rule.

Interpretation

The KG is strong as a curated retrieval and provenance graph: every criterion has evidence, domain/article metadata, and source provenance. The embedding benchmark is weaker because the graph is small and schema-driven, so TransE does not yet learn useful graph-completion structure.

Next improvement: add paper-level nodes such as claims, methods, experiments, datasets, results, limitations, citations, and evidence spans, then link them to review criteria.

  • Strong point: the KG is reliable for retrieving review criteria with provenance.
  • Weak point: the KG is not yet large or relationally rich enough for strong embedding prediction.
  • Practical conclusion: use Zaveri-style KG quality as the main evaluation, and treat PyKEEN as an exploratory secondary benchmark.

Recommended Next Benchmark

For this review system, retrieval evaluation should be added next. Create test queries such as TWELF educational technology proposal or ICLR ML paper, define the expected criteria, and measure Precision@K, Recall@K, and MRR. This would evaluate the system behavior more directly than link prediction.
